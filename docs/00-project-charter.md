# SSG Project Charter
Version 0.4.0-draft · 2026-11-06

## Purpose
SSG (working expansion: Symbolic Systems Grammar) separates a source's stable machine identity from its many symbolic, semantic, geometric, and visual projections. The central metaphor is the shadow: a traced outline is not the source object, but a useful projection with traceable origin.

## Accepted decisions
- Symmetry: configurable D4 + D8 + Adaptive profiles.
- Knowledge: graph-first canonical model; tree is a projection.
- Security: hybrid — standard cryptography for confidentiality/integrity, keyed glyph mapping for presentation only.
- Pipeline: SOURCE → KNOWLEDGE GRAPH → VISUAL SHADOW → RECONSTRUCTION.
- Repository: metsam-mastem/4.

## Non-goals
SSG does not replace Git or source-of-truth storage. A decorative poster is not a lossless backup. Fractals, glyph substitution, prime layouts, and shift registers are not cryptography. No universal ratio is assumed for all Iranian architecture.

## Principles
1. Stable identity independent of appearance.
2. Preserve original source and provenance.
3. Separate semantics, rendering, serialization, and cryptography.
4. Every transform declares lossless or lossy behavior.
5. Reversibility is proven by tests.
6. Every relation is typed and evidence-linked.
7. Geometry is parameterized and measured.
8. Exact constants and numeric approximations are stored separately.
9. Aesthetic profiles are configurable.
10. No destructive external action without explicit approval.

## Success criteria
100% resolvable source traceability; stable IDs across view-only renders; valid graph endpoints; deterministic manifests; exact hash equality after lossless round-trip; explicit NOT RUN status until tests execute.
